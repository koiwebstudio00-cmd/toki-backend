# Cierre de funcionalidades — 23/10/2026

Este repositorio vive localmente en `toki-backend`; su package y servicio se llaman `toki-api`. Acompaña al frontend `toki` en la rama `dev`.

## Cambios consolidados

- POS: cobrar y entregar o enviar a cocina. Pago pendiente en efectivo para retiro, cobro y entrega atómicos, efectivo recibido y vuelto persistidos.
- Clientes: creación, edición de contacto/direcciones, importación con vista previa y exportación paginada. Validaciones y aislamiento por negocio.
- Historial importado: almacenamiento separado de pedidos operativos, sin descontar stock ni generar cobros actuales. El frontend transforma CSV/XLSX a filas JSON.
- Avatar personal: firma de subida a R2, validación de propiedad y reemplazo/eliminación de la imagen anterior.
- Catálogo: unidad o kg, stock de tres decimales para peso, ajuste manual del total de la línea y snapshots de cálculo/unidad/ajuste. Los agregados conservan precios de base de datos y límites de selección. Peso online excluido.
- Agente: cantidades decimales compatibles al consultar; modificación de pedidos por peso derivada a una persona.

## Migraciones y arranque

Migraciones incluidas: `0019_pos_kitchen`, `0020_pos_pay_at_pickup`, `0021_imported_orders`, `0022_weighted_products`. Los productos existentes mantienen venta por unidad. No editar migraciones ya aplicadas.

En desarrollo local: `npm run db:generate`, `npm run db:migrate:deploy` y reiniciar el servidor. En producción seguir el entrypoint y procedimiento de despliegue del proyecto; el script migrate-dev es exclusivamente local.

El catálogo de prueba se carga desde el frontend con `npm run seed:catalog`: 18 productos y 6 categorías. No restablece stock ni modificaciones al repetirlo. Ver `toki/docs/CATALOG-SEED.md`.

## Verificación registrada

Build, lint y typecheck del backend aprobados. Pruebas de catálogo/peso: 24; regresión de pedidos/catálogo/agente: 145; dashboard: 17. Estas ejecuciones tienen pruebas en común y no deben sumarse como pruebas únicas. La suite completa detectó dos fallos de infraestructura en Windows: shell sh ausente y una expresión regular de configuración incompatible con CRLF. No se declara la suite completa verde.

`DATABASE_TEST_APP_PASSWORD` permite configurar la contraseña del rol toki_app al usar la base de pruebas aislada. El valor predeterminado sigue siendo el configurado por test:prepare. Tener en cuenta que los roles PostgreSQL son compartidos por las bases del mismo servidor; preparar tests y desarrollo puede cambiar la contraseña del mismo rol. Nunca usar la base operativa como DATABASE_URL_TEST.

Pendiente: peso online, integración de balanzas, combinación de peso con agregados y prueba de impresión/cámara con hardware real. No se hizo push ni despliegue en este cierre.
